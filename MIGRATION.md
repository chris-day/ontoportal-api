## Verification and privacy

The native `llmstxt` implementation in Zensical 0.0.71 generates `llms.txt`, 21 page Markdown exports, and `llms-full.txt` at the Pages project subpath. It needs no separate `mkdocs-llmstxt` package or preprocessing hook. The static checker compares every configured navigation and LLM selection with the public page set, checks built references and anchors, validates export links, checks the favicon and migration destinations, and rejects sensitive local identifiers. The browser checker exercises desktop and mobile pages, search, favicon decoding, repository links, and native consent. Its evidence is written outside the clean-build output directory by default to `/tmp/ontoportal-docs-evidence`.

Browser network inspection found only same-origin theme, search, and favicon requests before consent, after rejection, and after revocation. Enabling the optional GitHub category led to requests to `api.github.com` for repository and latest-release metadata. No analytics or external font requests were observed. Consent is stored under a scoped `__consent` local-storage key. **Accept** saved the selected checkbox state, not every possible category; reopening restored the selection. The built footer has a persistent settings link. These checks establish the observed browser behavior; they do not determine the legal obligations of a production deployment.

After reinstalling the recorded dependency files into the existing Python 3.14 `.venv`, `zensical build --clean --strict` produced no warnings. The static checker passed for 21 pages, 21 Markdown exports, and all 46 mapped source records. `pip check` found no broken requirements; the application suite had 6 passing tests and 3 intentionally skipped live API tests. Chromium checks passed after the final clean build with no JavaScript errors or failed resource requests. Desktop and mobile screenshots were visually reviewed. The detailed browser report and screenshots are under `/tmp/ontoportal-docs-evidence/`, outside the clean-build directory.
